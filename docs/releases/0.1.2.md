# t4a-cuda-kernels 0.1.2

Version 0.1.1 is on crates.io with different contents than `main`, so the number cannot be reused: `cargo update` on 0.1.1
would keep the old code while `main` carries the fixes below. 0.1.2 is that content under a number that identifies it.

## What changed since the published 0.1.1

- **Split pass 1 of `reduce` assigns lanes by group, and the ABI documents it** (`docs/abi/c-kernel-abi.md`, revision 13).
  `T4A_CUDA_ABI_REVISION` is 13 in `cuda/include/t4a/abi.cuh`.
- **`reduce.cu` forms no pointer before the stride check**, so a strided axis no longer builds an out-of-allocation pointer.
- **The evidence harness checks every CUDA call.** `bit-identity.cu` ignored the return values and could print
  `mismatches 0` after a failed `cudaMalloc`/`cudaMemcpy`; it now exits 1 on a mismatch and 2 on a CUDA failure, and both
  paths are demonstrated in `docs/worklogs/evidence/2026-11-08-nan-extrema-select/bit-identity-determinism.log`
  (`inject-mismatch` → exit 1, `inject-download` → `invalid argument`, exit 2).
- **The first hosted CI lanes** for this repository: compile-only for every `cuda/src/*.cu`, plus the host test suite and a
  check that a pull request states how it was verified.

## What is not claimed

The 2x gap to PyTorch on the full-array reduce is not closed. `docs` measure ~2.7-3.5x at n=2^24 with a per-call floor
around 13.5 us; removing the standalone-wait would be needed to go further, and that is out of scope here.
